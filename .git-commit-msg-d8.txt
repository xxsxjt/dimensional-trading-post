fix: 派遣 —— 出远门的人还站在柜台上（D8）

缺陷 D8：dispatched 与 activated 从来没有互斥过

UI 的 renderNpcQueue 只看 npc.activated 判断「是否已处理」，
shop 的 activateNpc 也只看 npc.activated，
dispatched 从来没被这两处读过。

于是玩家把商旅派去近郊跑单（1~7 天），他还在今日商旅队列里，
还挂着一个「接待」按钮 —— 点下去就被请上了柜台。

后果是实打实的：
1. 无限白嫖每位被派出的商旅的带货（那是前期唯一的进货渠道）；
2. 成交后 activated 变 true，他回来以后没法再接待 —— 这趟白跑；
3. 最糟的顺序是「先成交、再归来」：他既没货也没生意可做。

修法（三处一起，这条状态有三个读点）：
- src/wasteland-ui.js renderNpcQueue：读 npc.dispatched，
  「在途」是第三种状态 —— 不能接待，但也不能算已接待；
  标「出远门」，队头的待接待计数也只数既没接待也没在途的人；
- src/wasteland-shop.js activateNpc：加 dispatched 拦截，
  绕过 UI 直接调 API 也别想把人叫上柜台；
- src/wasteland-shop.js _renderNpcQueueFallback：同一条路也要拦，
  否则「模块缺失时」旧缺陷从 fallback 复活。

回归与验证：
- 新增 tests/dispatch-away-merchant.cjs（7 项）：
  队列不再有「接待」按钮 / 标出「出远门」 / 在店的人照常可接待 /
  绕开 UI 直接调也不能上柜台 / 归来后重新可接待 /
  dispatched 与 activated 互斥 / fallback 路径同样拦得住；
- 变异验证新增 M20/M21/M22，把三处修复逐个注回源码，
  派遣变异验证从 19/19 变成 22/22；
- verify-claims.mjs 新增九条源码级断言（D8-1~9）。

附带修掉两条**测试自己的缺陷**（都在 7ef7940 上同样会红，不是本轮引入）：

T1 tests/faction-rules.cjs
「40 天连续成交」其实只成交了 4~5 次 —— 它从来不进货，
开局 5 件起始物品卖完就没有货了。后面 35 天一次都成交不了，
而这几次恰好全落在拾荒者阵营的概率不小，于是 touched.length >= 2 偶发红。
修法：每天先进货再卖货（顺序不能反：成交会把 npcId 清成 null，
之后再 onTakeOffer 就静默失效了），并加一条前置条件自检
（必须真的成交 ≥ 10 次，否则测的是运气不是阵营系统）。
300 个种子最少成交 13 次、最少碰到 3 个阵营、零失败；500 次连跑全绿。

T2 tests/dispatch-rare-gate.cjs
「深入禁区稀有品出现率」用的是单边手调容差 rate < doubleCounted - 0.02，
离真值只有 2.3σ（σ≈1.07%），每次跑约 1% 概率假红 —— 60 次红 1 次，与推算吻合。
根子是「门槛被架空」这个缺陷信号太弱：声明 20%、失效后 24.4%，
只差 4.4 个百分点，而抽样误差就有 ±1 个百分点。
修法两条一起：
(1) 沙箱只建一次（以前每抽一次样就重建 vm context 并全量重解析 core 源码），
    成本降到几乎为零，样本量从 600/400 提到 3000/3000；
(2) 判据换成双向、容差按 σ 自动缩放（4σ），
    既不能高于双重计入上界，也不能低于声明值 − 4σ。
80 次连跑全绿；派遣变异验证 22/22 依然全部被抓住 —— 牙齿没掉。
